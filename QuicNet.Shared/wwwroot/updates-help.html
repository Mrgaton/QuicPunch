Volver a Actualizaciones

Ayuda con las actualizaciones

Comprueba tu versión, elige qué actualizaciones recibir y resuelve los problemas de descarga o instalación.

Buscar e instalar una actualización

  1. Abre Ajustes → Actualizaciones. Allí aparecen tu versión y la última comprobación.
  2. Pulsa Buscar ahora. Si hay una versión más reciente, verás la versión publicada y el botón para instalarla.
  3. En Windows, pulsa Instalar y reiniciar. En Android, pulsa Instalar actualización y continúa en el instalador del sistema.

Con Descargar e instalar actualizaciones automáticamente activado, QuicNet comprueba al abrir y cada 15 minutos. Si lo desactivas, puedes buscar e instalar manualmente desde esta misma pantalla.

Las descargas se verifican antes de instalarlas. Una actualización conserva los datos de la aplicación.

Elegir Estable o Beta

Estable recibe las versiones publicadas para uso habitual. Beta incluye versiones de prueba y versiones estables; recibe la compilación más reciente de ambos canales.

La elección se guarda en este dispositivo. Instalar una versión estable mientras estás en Beta no cambia tu canal: seguirás recibiendo las próximas pruebas.

Al volver a Estable, QuicNet conserva la versión instalada y espera una compilación estable superior. El cambio de canal no instala una versión anterior ni borra tus datos.

Qué esperar al instalar

Windows

QuicNet sustituye el archivo EXE y se reinicia. La instalación automática espera a que terminen las llamadas. Guarda el EXE en una carpeta donde tengas permiso de escritura.

Se conserva una copia de la versión anterior para recuperarla si la nueva no arranca.

Android

QuicNet descarga la APK y abre el instalador de Android. El sistema puede pedirte autorización para instalar desde esta fuente; revisa su solicitud y confirma la instalación si quieres continuar.

Si cierras el instalador, vuelve a Actualizaciones y pulsa Instalar actualización para abrirlo de nuevo. Para actualizar sobre la aplicación existente y conservar sus datos debe mantenerse el mismo certificado de firma.

Si algo no funciona

  • No se puede consultar o descargar: comprueba tu conexión y pulsa Buscar ahora para reintentar. Con las actualizaciones automáticas activadas, un fallo del servidor se vuelve a intentar cada minuto.
  • La actualización está lista pero no se instala: revisa el mensaje de estado. En Windows puede estar esperando a que termine una llamada; en Android puede faltar la confirmación del instalador.
  • La instalación anterior falló: se conserva la versión actual. Puedes volver a pulsar Instalar o esperar una nueva publicación.
  • Error de firma o de integridad: el archivo no ha superado la verificación y no se instala. Vuelve a buscar la actualización; si el error continúa, conserva la versión actual y espera una publicación válida.
  • La aplicación indica que está al día tras cambiar de canal: puede que aún no exista una compilación superior en el canal elegido. Puedes seguir usando tu versión actual.

Si tu versión es anterior al sistema de actualizaciones, descarga la aplicación desde la página de descargas de QuicNet e instala la actualización manualmente.

Publicar versiones (desarrollo)

Estas instrucciones son para quien mantiene y publica QuicNet. Las versiones se distribuyen desde cdn.gato.ovh/QuicNet. El EXE AOT y la APK comparten una versión y un número de compilación creciente.

  1. Abre el repositorio y lee doc/deployment/auto-updates.md. Conserva las claves de firma existentes.
  2. Elige una versión y un Build mayor que los publicados en Estable y Beta. Ejecuta las pruebas.
  3. Prepara una prueba en el canal Beta con PowerShell 7. Los valores siguientes son ejemplos: sustitúyelos por la versión y el Build que hayas elegido.
    ./scripts/publish-updates.ps1 -Version 1.1.11 -Build 13 -Channel beta -LocalOnly
  4. Revisa la compilación y publica los mismos archivos:
    ./scripts/publish-updates.ps1 -Version 1.1.11 -Build 13 -Channel beta -SkipBuild -CdnRoot 'Z:\CDN\QuicNet'
  5. Verifica por HTTPS el manifiesto y prueba una actualización en PC y Android.

El script incorpora las bibliotecas al EXE AOT, firma la APK, calcula los hashes, firma el manifiesto y sube primero los archivos. Solo al terminar activa la nueva versión.

No copies claves privadas al servidor. No sobrescribas archivos de una versión publicada: incrementa Build.

Beta publica latest-beta.json y conserva intacto latest.json, el canal Estable. Para publicar una versión definitiva, recompila con un Build superior y -Channel stable.
