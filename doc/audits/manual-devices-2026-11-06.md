# Revisión manual con dispositivos reales — 2026-11-06/07

Revisión de la aplicación Windows en ejecución y el móvil del propietario, en una llamada existente. Se trabajó con una pestaña oculta y una ventana propia sin activación; no se reinició ninguna aplicación ni se ejecutaron suites de tests. La conexión observada era QUIC en la red local; esto no valida cambios Wi-Fi/datos móviles ni una conexión WAN.

## Resultados observados

- **Archivo:** `QuicNet-demostracion.txt`, contenido ficticio de 166 912 bytes. El móvil lo descargó y el emisor recibió el acuse de integridad: «Recibido y verificado por el contacto».
- **Apertura Android:** el propietario reprodujo el error `UseShellExecute` al abrirlo. Se añadió apertura nativa con un proveedor privado de contenido y permiso temporal de lectura por adjunto. El servidor resuelve únicamente archivos registrados por conversación e identificador. Falta verificarlo con Android actualizado.
- **Confirmación del archivo:** recargar el emisor hacía volver el estado verificado a «Disponible para que el contacto lo descargue». Se persiste el recibo verificado en el registro de transferencias y se restaura con el historial. El proceso Windows en ejecución conserva el backend anterior; falta repetir tras actualizarlo.
- **Cámara Android → Windows:** se recibió H.264 a 720×1280, aproximadamente 30 paquetes de vídeo/s y 2,5 Mbps. El canvas receptor se hizo visible con las dimensiones del fotograma decodificado. El propietario confirmó vídeo en el móvil y cambio entre cámaras.
- **Selección de cámara:** el propietario necesitaba apagar/reactivar el vídeo para acceder a una lista con una frontal y tres traseras indistinguibles. El control estaba dentro de los ajustes de audio. Ahora aparece en la propia llamada, con cambio frontal/trasera directo y selección automática por orientación o específica por identificador. Las etiquetas usan capacidades o nombres declarados por el dispositivo; no se inventan tipos de lente. La reapertura puede causar una pausa breve de vídeo, conservando el audio; un fallo indica que el vídeo está desactivado.
- **Pantalla Windows → Android:** una ventana propia de demostración, detrás de las demás ventanas y sin datos personales, se transmitió mediante `h264_nvenc`, 800×480 y objetivo de 60 FPS. El propietario confirmó el contador y la animación en movimiento. Después se detuvo exclusivamente esa transmisión y se cerró la ventana de demostración.
- **Receptor en segundo plano:** el primer intento de pantalla falló por falta de respuesta a la comprobación de decodificación. Con el móvil activo, el segundo intento funcionó. El backend antiguo aún impone ese veto; la versión del código revisada trata la comprobación como diagnóstico.
- **Selector de pantalla:** se reprodujeron previews pendientes durante más de un minuto. El cliente ahora limita su espera, prioriza la selección y cancela las solicitudes al filtrar/cerrar. La selección filtrada cargó una imagen completa en aproximadamente 1,5 segundos; con cero coincidencias, Compartir quedó desactivado.
- **Chat estrecho:** a 390 píxeles, los botones recortaban el nombre del adjunto. Las acciones pasan debajo del nombre y estado, verificado visualmente en la aplicación real.
- **Indicadores de vídeo:** se ocultaba «Conectando vídeo» al recibir un paquete, antes de decodificarlo. Se cambió para esperar un dibujo satisfactorio o fotograma presentado por el elemento de vídeo; la telemetría separa paquetes recibidos y FPS reproducidos. La llamada terminó por acción confirmada del propietario antes de medir esta última revisión en directo.

## Alcance de la comprobación del código

Comprobación de sintaxis de los JavaScript modificados y compilación limitada de Shared/Android, sin generar ni instalar una nueva APK. Se generaron también el adaptador Java y el manifiesto final de Android: un único proveedor `org.quicpunch.androidprobe.chatfiles`, con `exported="false"` y `grantUriPermissions="true"`. Las correcciones nativas requieren actualizar los dispositivos para validarlas en ejecución. No se ha comprobado la apertura Android corregida, persistencia del acuse con el nuevo backend ni selección de lentes con la interfaz móvil actualizada.

No se interrumpió la llamada existente: terminó después por acción del propietario, que lo confirmó. Solo se transmitieron el archivo ficticio y la ventana de demostración; no se compartieron archivos personales ni el escritorio completo. Las capturas de interfaz y la fuente de demostración son resultados regenerables en `.artifacts/manual-device-review/`.
